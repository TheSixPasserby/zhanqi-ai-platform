## 关键判断（为什么这么改）

**① `\n` 的真正根因是 SQL 转义写多了一层。**
生成 SQL 时我写成了 `\\n`（4 个反斜杠），MySQL 解析后得到的是**字面反斜杠 n**，不是换行。
正确的写法在 SQL 字符串里只需要 `\n`（1 个反斜杠 + n）—— 实测 `SELECT HEX('a\nb')` 得到 `610A62`，
说明单个反斜杠才会被解析成真换行。
这次是**数据和渲染两侧都要改**：数据改成真换行之后，前端还必须 `white-space: pre-wrap`，
否则 HTML 会把换行折叠成一个空格，长文案还是挤成一整块。只改一边都不算修好。

**② 聊天空白不是输入框的问题，是 flex 布局的方向问题。**
`.chat-body` 是 `display:flex; flex-direction:column`，消息从**顶部**开始堆叠，
消息少时下面自然空出一大片。用户看到的「发送消息后聊天框出现空白」正是这块。
清空输入框完全解决不了 —— 空白在消息列表末尾，跟输入框没有关系。
正确做法是给消息组加 `margin-top:auto`，把整组压到底部，空白集中到上方（聊天界面的标准形态）。
**商户端看起来最严重**，是因为它的聊天区高度是 `calc(100vh - 178px)`（比游客端高很多），
而演示会话只有十来条消息，底部空白能占到面板的三分之二。
验证时要注意：消息多到溢出时 `margin-top:auto` 按 CSS 规范**不生效**（没有剩余空间可分），
这时表现为「正常滚动到底」，不是 bug。所以验收必须用**消息少**的会话来测（m3 只有 3 条）。

**③ 主题只覆盖设计令牌，是最不容易漏的做法。**
三端的卡片 / 弹窗 / 表格 / 输入框底色全部引用 `app.css` 里的 CSS 变量。
只要在 `html[data-theme=dark]` 上重定义这批令牌，整站就一起变深。
如果逐个组件写深色样式，必然出现「卡片黑了、弹窗还白」的割裂 —— 而且每加一个组件都要记得补。
代价是要把**少数写死浅色值**的地方单独列出来覆盖（聊天区渐变、抽屉白底、导航条、
菜单图标的行内 style），这些集中在 `theme-dark.css` 末尾，加新组件时照着那几类补即可。

**④ 首屏防闪是主题脚本必须提前加载的原因。**
`theme.js` 放在 `<head>` 里同步执行（早于 body 渲染），先给 `<html>` 打 `data-theme`。
如果放在 body 末尾，用户会看到「先白后黑」闪一下。这也是它不并进 `app.js` 的原因。

**⑤ 头像点击跳个人中心，是把快捷入口收回到唯一出口。**
之前顶部头像既能换头像、又能改密码，和商户端/管理端的 el-dropdown 口径不一致。
现在头像点击统一跳个人中心，换头像与改密码都在那里做；悬浮窗只留导航类入口。
顺带发现：个人中心原本**没有**换头像和改密码入口（旧实现被删过），所以补回去了，
否则「改密码只能在个人中心」就变成了「哪里都不能改」。

## 踩过的坑

**① 测试用 `innerText` 读不到悬浮窗文案。**
`.user-menu` 是 `opacity:0` + `visibility:hidden`，`innerText` 对不可见元素返回空串，
元素明明有 5 项却全部读出 `""`。改用 `textContent` 才对。

**② `margin-top:auto` 在内容溢出时是 0px，看起来像没生效。**
一开始用消息多的会话（m1 有 13 条）验证，读到 `marginTop: 0px`、`firstTop: -460`，
误判成规则被覆盖。实际是空间不足时 auto 按规范归零，`scrollTop:480` 说明已正常滚到底。
换消息少的会话（m3，3 条）后 `marginTop` 计算为 342px，一切正常。
**教训：验证布局效果要先确认前提条件成立（这里前提是「有剩余空间」）。**

**③ 演示数据里有跨账号的孤儿会话。**
m7 的两条消息属于已删除的 `u14`，小帅看不到；且 m7 商家本身已不存在，
接口直接返回「商家不存在」。验收时先查 `chatMessages` 的 `(merchantId, buyerId)` 分布，
挑一个**当前账号真的有会话且消息少**的组合，不要想当然。

**④ theme-dark 里第一批选择器是猜的类名。**
我按 `.pc-header` / `.admin-head` 写，实际项目里是 `.topnav` / `.auth-head` / `.side`，
结果导航栏在深色下还是白的（截图一眼看出）。改成真实类名后才对。
教训：写覆盖样式前先用 grep 确认选择器真的存在，别凭印象。

## 遗留问题

1. **深色下个别行内写死的色块靠降透明度处理**（菜单图标小底块），不是精确配色；
   要做到完全统一，应把这些行内 `style` 改成 CSS 变量。
2. **Element UI 的深色覆盖是「够用」级别**，不是官方 dark 主题。
   已覆盖表格、输入框、下拉、日期面板、分页、消息框；少数冷门组件（级联选择、树）未逐一验证。
3. **主题偏好全局共享**（一个 key），不按端隔离 —— 这是刻意的：
   用户在哪端选了深色，换端也该是深色。如果以后要按端区分，改 `theme.js` 的 KEY 即可。
4. **PC 点位图集没有做「暂停轮播」交互**（鼠标悬停不暂停）。
   演示够用；真实产品建议 hover 时暂停，避免用户正在看图时被切走。
5. **`\n` 修复依赖 `seed-gallery.sql` 重跑**。若部署机已有旧数据且不重跑脚本，
   库里仍是字面 `\n` —— 但前端 `pre-wrap` 只解决「不折叠」，不会把字面 `\n` 变成换行，
   **所以数据脚本必须跑一次**。这一点要写进升级说明。
