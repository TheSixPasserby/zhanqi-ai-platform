# 新增部署配置解析的常驻回归测试（守住 port 同名键那个 P0）

- 日期：2026-09-29
- 作者：Windows 侧 agent（提交身份用操作者本人的 GitHub 账号）
- 分支 / PR：`chore/deploy-config-test`

## 做了什么、为什么

HANDOVER 待办里挂着一条：`Get-ConfigValue` 的块查找**没有常驻回归测试**，
一直是人工「连跑两次部署看看端口有没有被写坏」验证的 —— 下一次重构没有护栏。

这个坑值得一条断言守着，因为它是本项目最阴的一个：
`config/application.yml` 里 `app.port`（8080）与 `app.database.port`（3306）
**键名都是 `port`**，取值一旦退化成「全文找第一个 `port:`」，读到的永远是 8080；
它再被写回 `database.port`，配置就永久毒化。**首次部署不发作（还没有配置文件），
第二次起才发作**，而且两侧报错都指向 MySQL。它在 Windows 与 macOS 两条线上
被**各自独立踩到过**，还各写了一版修复 —— 这种坑不配一条常驻断言说不过去。

新增 `tools/deploy-config-test.js`：**36 项断言，零 npm 依赖，离线可跑**。

## 怎么测的：抽交付版的函数体来跑，而不是复制一份实现

这是这个脚本唯一重要的设计决定。如果测试里自己实现一套解析逻辑，
那么「有人把 deploy.ps1 改坏了、测试却还绿着」就是迟早的事。

- **ps1 侧**：用花括号配对（会跳过字符串与注释里的括号）从 `tools/deploy.ps1`
  里抽出 `Get-ConfigValue` 原样喂给 PowerShell 执行；
- **bash 侧**：同样从 `tools/deploy.sh` 抽出 `get_config_value` 交给 `bash` 执行。

顺带加了一条元断言：**抽出来的函数签名必须仍然带 `$section` 参数** ——
签名变了就说明有人动了取配置的接口，用例要同步。

## 关键决策与取舍

- **夹具必须先自证「真的能触发老写法」**。测试开头会用一个「全文找第一个 `port:`」
  的参照实现在同一份夹具上跑一遍，断言它读到的是 **8080**。
  如果哪天夹具被改温柔了（比如把 `app.port` 挪到后面），这条会先红 ——
  否则后面一长串断言看着全绿，其实什么都没守住。
- **ps1 的临时 runner 必须写成 UTF-8 带 BOM**。抽出来的函数体里有中文注释，
  而无 BOM 的 `.ps1` 会被 PowerShell 5.1 按 GBK 读、足以读坏语法。
  这个坑当天刚在别处踩过（见 `2026-09-29-verify-reset-on-windows.md`），
  这回直接规避。
- **失败时保留临时目录**（打印路径）。生成 runner 这种东西，出错时看得到现场
  比省那点磁盘空间重要得多 —— 本条其实是踩出来的：第一次跑就是生成的
  PowerShell 数组**尾逗号**报了「, 后面缺少表达式」，保留现场一眼就定位了。
- **PS 里的路径用正斜杠**。`JSON.stringify` 会把 `C:\Users\...` 写成
  `"C:\\Users\\..."`，Windows 虽然认，但在 `.ps1` 里读起来像转义序列，白添困惑。

## 最重要的一步：验证「测试真的能红」

一个跑得绿的测试不等于一个能抓到问题的测试。所以把 `deploy.ps1` 的块限定
临时打坏（把 `if ($section) {` 改成 `if ($false) {`，等价于退回全文匹配），
跑一遍：

```
打坏后 测试退出码 = 1（期望非 0）
打坏后 汇总 = 通过 30 项，失败 7 项
核心用例是否报红 = 是      （database.port 取到 3306）
越界用例是否报红 = 是      （块后面同名键不越界）
还原后 sha 与原文完全一致 ✅
```

**7 项报红、退出码非 0**，说明护栏是真的；还原用原始 Buffer 写回，
比对 sha 确认 `deploy.ps1` 一个字节没动。

## 顺带实测出的一处真实差异（不是推测）

bash 版与 ps1 版**取配置的实现并不真的对等**。测试第 4 节把两侧实测值打出来：

| 场景 | ps1 实测 | bash 实测 |
| --- | --- | --- |
| 值带行尾注释（`port: 3307   # 装在 3307`） | `3307` | `3307   # 装在 3307` |
| `database:` 缩进 6 格（非两格） | `3310` | `FALLBACK`（认不出块） |

即：bash 版把 `database:` 的缩进**写死成两格**、也不**剥行尾注释**。
日常不会触发（配置由脚本按固定模板生成，缩进与注释都是固定的），
但**用户手改过配置就会** —— 比如给端口加个行尾注释，bash 侧拿到的就是脏值。

**这次没有顺手改掉它**：修法要用到 awk/sed，而本机是 Windows（Git Bash 是 GNU 工具），
验证不了 macOS 上的 BSD awk/sed 行为。按 `AGENTS.md` 的「改一边必须同步另一边」，
在验证不了的环境里动 `deploy.sh` 反而更危险。所以登记成待办，并在测试里
把差异显式打印出来（不参与断言，但一眼可见）。
