# 游客端排版修复：AI 助手自适应、聊天顶部错位、选项框与内容衔接

- 日期：2026-10-31
- 作者：spsCiallo（AI agent 协作）
- 分支 / PR：feat/virtual-map-ai-split-4themes

## 做了什么、为什么

游客端合并成一套自适应页面之后，宽屏规则是用「手机壳」样式表加媒体查询硬掰出来的，留下了几处只在特定宽度才暴露的排版问题。本轮按「先量后改」的顺序把它们逐个定位并修掉：

1. **AI 助手整页高度塌陷**。`.chat-page` 只有 `display:flex; flex-direction:column`，没有高度约束，整页按内容撑开——375x667 下实测只有 411px 高，输入区停在半页中间，下面留 264px 空白；对话变长后又变成整页滚动，输入区跟着页面走。改成一屏三段式：页面锁 `100dvh`、消息区 `flex:1 + min-height:0 + overflow-y:auto`、输入区 `flex:none`（并删掉了原来那个参照系错误的 `position:sticky; bottom:0`）。桌面档再扣掉顶部导航的 69px（68 高 + 1px 边框）并清掉 `.page-body` 统一写的 40px 底内边距。
2. **聊天界面顶部错位**。`.im-topbar` 在 375/414/768/1024/1440 五档下宽度都只有 200px，返回键、标题、举报按钮挤在中间一小块绿底上。根因不是宽度写错，是 `@media (max-width:1023px)` 里那句 `.page-body, .topbar { margin-left:auto; margin-right:auto }`——`.im-page` 是纵向 flex 容器，顶栏作为 flex item，**auto 左右外边距会取消 stretch**，于是缩成内容宽度。修法是给 `.im-page > .topbar` / `.chat-page > .topbar` 显式 `align-self:stretch` 并清掉 auto 外边距。
3. **1024px 宽度整站横向溢出**。7 档宽度 × 10 个视图扫描，只有 1024x768 溢出（scrollWidth 1091 > clientWidth 1024），offenders 全是 `.nav-right` 系。原因是 8 个导航项 + 搜索框 + 3 个按钮在这一档放不下。修法不只是缩字号，而是在 1024–1160 区间把导航项文字收起（`span{display:none}`，只留图标 + `:title` 悬停提示），1161px 以上文字恢复正常。
4. **选项框（Tab / 筛选）与内容割裂**。村内地图的筛选按钮 `<button class="chip">` **完全没有样式**——样式表里只有 `.chips`（容器）与 `.chips button`（子按钮），`.chip` 从未定义，实测是浏览器默认按钮（灰底、2px outset 黑边、圆角 0）。同时把 `.tabs-pad` 从「与正文同底色的 14px 灰缝」改成白底 + 下边框的工具条，让选项条与下方卡片形成明确层次。顺带用脚本比对 333 个静态 class 与全部 CSS，补掉 `.search`、`.field-row` 两个同样漏定义的类。
5. **电脑端底部操作条（立即预约 / 提交订单）**。手机上是贴底通栏，电脑上照搬会让「合计 ¥256」在最左、按钮在最右，中间空出一米。改成底栏本身仍通栏、用左右 padding 把内容挤回 1128px 正文宽度。
6. **地图标签压住别人的图标**。上一轮只保证了「标签之间不相交」，去量才发现桌面档有 45 处、手机档 50 处标签盖住邻近圆点，看着像那个点位没标出来。在标签避让里把其他圆点的矩形也当障碍物加入判定（间距比标签之间松 1px，避免标签被迫飞太远）。

## 关键决策与取舍

- **触屏端的 `100dvh` 与 `100vh` 同时写**：先写 `100vh` 兜底（老浏览器不认 dvh），再写 `100dvh` 覆盖。移动端地址栏收放时 `100vh` 会把输入区顶出屏幕，这是必须的取舍，不能只写一个。
- **1024–1160 档收文字而不是减项目**：导航 8 项是产品定的，不能删；缩字号到 13px 仍放不下。收起文字只留图标是最小信息损失方案，且每个 `a` 都补了 `:title`，桌面有鼠标悬停可看全称。
- **底部操作条通栏而非浮动卡片**：先试了「浮在内容区底部的一枚圆角卡片」，1440 下很好看，但 1024 下左右留边只有 18px、看起来像被屏幕切了一刀。最终选通栏 + 内容内缩，两种宽度都稳定。
- **标签避让把圆点当障碍物时 pad 单独取值**：与标签之间用 `pad`，与圆点用 `pad + 1`。如果同值，密集区会出现标签被推到离自己点位很远的地方，反而更难读。

## 踩坑与排查过程

- **改了 CSS 但 probe 读到旧值**：服务跑的是没带 `--spring.web.resources.static-locations=file:...` 的实例，静态资源从 jar 里读，改文件不生效。白查了一轮，误以为修法无效。教训：改前端必须用带 file: 静态目录的启动脚本，并在改动后确认新规则真的进了 computed style。
- **`margin:auto` 在 flex 容器里会取消 stretch**：这是聊天顶栏只有 200px 宽的真因，也是本轮最有价值的发现。直觉会去查宽度、查 padding、查 flex-basis，全都正常——因为问题不在「给了多少」，而在「没收满」。
- **`.chip` 从未定义**：这类「类名拼错/漏定义」用眼睛看代码很难发现，因为 HTML 里写了 class、CSS 里也有一堆 chip 开头的规则。最后是写脚本把静态 HTML/JS 模板里的 333 个 class 与全部 CSS 选择器做差集才翻出来。同样的方法又翻出 `.search` 与 `.field-row`。
- **注入了登录态仍停在登录页**：只写 `localStorage['zhanqi.visitor.token']` 不够，还要写 `localStorage['zhanqi.visitor.user']`（JSON `{role,name,at}`）。
- **CRLF**：visitor.css 与 visitor/index.html 都是 CRLF，按 `\n` 拼的替换串永远匹配失败。先做一次全量换行归一化再改。

## 沉淀到记忆的条目

- flex 纵向容器里，子项的 `margin-left/right:auto` 会取消 `stretch`，元素缩成内容宽度（聊天顶栏 200px 的真因）。
- 改前端静态资源时服务必须以 `--spring.web.resources.static-locations=file:...` 启动，否则读的是 jar 内旧资源。
- 用脚本把静态模板里的 class 与 CSS 选择器做差集，能揪出「HTML 写了 class 但 CSS 从未定义」这类肉眼难查的问题。
- 地图标签避让除「标签 vs 标签」外，还要把「标签 vs 其他圆点」纳入判定，否则密集区会出现标签压住邻近图标。
