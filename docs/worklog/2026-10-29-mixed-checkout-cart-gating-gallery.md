## 为什么这么改（关键判断）

**1. 逐项表单必须从后端做起。**
只改前端是不够的：老 `createOrders` 只有一组顶层 `bookDate` / `people` / `address`，
所有商品共用。前端就算画出 4 个表单，提交时也只有一份值能落库，后一个会覆盖前一个。
所以先让 `createOrders` 支持 item 级参数（item 有值用 item 的，没有回落顶层，兼容老调用），
前端才有意义。这也是唯一能保证「民宿 12-08→12-11、研学 12-05、农事 12-15」各不串的方式。

**2. 购物车准入做双层。**
前端 `addCart` 拦一次是体验层（给出提示并直接跳到详情，用户不会卡住）；
后端 `createOrders` 的分类校验是安全层 —— 预约类缺日期本来就会被拒。
只有前端拦，绕过前端（直接调接口）就失效；只有后端拦，用户体验是「点了没反应」。

**3. 图集用 `UPDATE` 脚本而不是塞进 `seed.sql`。**
`seed.sql` 是 `INSERT IGNORE`，对已存在的老库完全不生效。
补内容必须用 `UPDATE`，所以单独做了 `seed-gallery.sql` + `tools/seed-gallery.js`，幂等。

**4. 图片来源的取舍（重要）。**
演示机离线、不能联网下图。我没有去网上找图（也做不到），而是把现有 18 张实景照片
裁出不同取景作为第 2、3 张（`-p2` / `-p3`）。
这样画面确实不同、仍然对应该点位，不是拿无关图片凑数。
**生产改造点**：换成摄影师实拍多角度图时，只改 `images` 数组，前端不用动。

**5. D1/D2 不居中的真正原因。**
不是缺 `display:flex`，而是**被覆盖了**：
`.day-badge { display:flex }` 特异度 0,1,0，而下面那条 `.day-head span { display:block }`
特异度 0,1,1，同层级更高，把 flex 盖成了 block，文字就靠左贴边了。
修法是把类名写成 `.day-head .day-badge`（0,2,0）压回去，而不是加 `!important`。

**6. 「未提交订单串单」的真实机制。**
不是订单数据串了，而是**视图状态串了**：点「我的订单」只改了 `view`，
`checkoutMode` 还是 `true`，于是页面渲染的仍是「确认订单」那一屏，
而它读的是购物车 —— 用户看到的就是「跳到了那笔没提交的单」。
修法是所有订单入口统一走 `openOrders()`，明确退出结算态但保留购物车。

## 踩过的坑

**① 我又犯了同一个错误 —— 用 `write` 覆盖 CSS。**
上次（2026-10-29 早）刚因为 `write` 覆盖 `pc.css` 丢了 150 个选择器，这次追加样式时
**又犯了**：`visitor.css` 丢 12 个、`pc.css` 丢 159 个。
原因是 `write` 前读到的内容比磁盘旧，覆盖后中间整块被抹掉，且没有任何报错。
已全部从 `HEAD` 恢复并用「读 + 追加 + 立即写回」的方式重做，并写了选择器集合差校验确认无丢失。
教训已更新到 `docs/agent-memory.md`。

**② `submitCart` 里调用 `syncCart()` 会吃掉用户填的表单。**
`syncCart` 用 `localStorage` 重建 `cart` 对象，表单存在 `cart[i].form` 上，一同步就没了 ——
表现为「填好的日期突然变回默认值」。改成提交前把内存 cart（含 form）写回本地，不再反向同步。

**③ `startCheckout` 里调 `this.go('orders')` 会立刻关掉结算态。**
因为我在 `go()` 里加了「进订单列表就退出结算」的逻辑，`startCheckout` 自己触发了它。
改成直接切 `view`，不走 `go()`。这个坑很隐蔽：`checkoutMode` 设为 true 后立刻被置回 false，
页面显示订单列表，看起来像「结算功能坏了」。

**④ computed 里定义的方法不能在模板里带参数调用。**
`checkoutLines()` 带括号就会被当成方法，必须放 `methods`；
而 `spotImages` / `productImages` 在模板里当属性用，必须放 `computed`。
放错位置的表现是 `undefined` 或 `is not a function`，而不是语法错误。

**⑤ 生成的 SQL 转义层层叠加。**
用 Node 生成 SQL 时 `\\n` 经多次字符串化变成 4 个反斜杠，MySQL 报 `Unknown command '\'`；
以及追加文案时把引号插到了字符串结尾之后，导致 `desc` 提前闭合。
最后用 Python 按字节替换 + 引号奇偶校验修好。

**⑥ 本机 mysql CLI 会卡住。**
多次并发调用后 `mysql.exe` 挂起不返回，导致 `node tools/seed-gallery.js` 超时。
清数据时改用 jshell + JDBC 绕开；生产脚本仍保留 mysql CLI（有 `MYSQL_BIN` 可覆盖），
但建议后续改成 JDBC 实现以彻底避开这个问题。

## 遗留问题

1. **「待付款」仍未实现**：项目无支付通道，用 `pending（待商家确认）` 表达。
2. **图片是裁切变体，不是实拍多角度**。演示够用，真实项目需换实拍图（只改 `images` 数组）。
3. **门店端购物车没有做「预约类混入」的历史数据清理**：如果用户上一版加购过预约类商品，
旧购物车数据里仍可能有一条。当前 `checkoutLines()` 会按 category 正确渲染它的表单，不会崩，
但更干净的做法是读购物车时按准入规则过滤一遍。
4. **`seed-gallery.js` 依赖 mysql CLI**，本机已出现卡死，建议后续改 JDBC。
5. **PC 端混合同样支持**，但 PC 端只有实物加购路径，混合场景主要发生在 H5；
PC 购物车抽屉里的逐项表单已实现，未做单独的自动化用例（由 H5 的同类逻辑覆盖）。
