# 游客端：电脑版顶部总览区改版、个人中心精简、导航头像改图片

- 日期：2026-11-01
- 作者：lead（AI agent）
- 分支 / PR：feat/virtual-map-ai-split-4themes

## 做了什么、为什么

这一轮是「把手机端合并成唯一游客端」之后的收尾打磨，用户提了三件具体的观感问题：

1. **电脑版顶部总览区太突兀**。合并游客端时，所有子页面沿用手机端的深绿渐变
   `.topbar`（手机上是替代标题栏的省空间做法）。在 414px 宽的手机上它是合理的，
   但放到 1180px 宽的电脑页面上就变成一整条横贯的深绿色带：上方是白色导航、下方是
   浅色卡片区，中间夹一条饱和绿，视觉上被切成三段。改法是把**页面级** `.topbar` 在
   `@media (min-width:1024px)` 内降级成「页面标题区」——透明底、无分隔线、深色标题
   21px、副标题 12.5px 灰、返回键从半透明白圆按钮换成白底描边圆按钮；打卡进度条并进
   这块区域（细进度 + 一行说明）而不是单独一条；商城的搜索框从标题下方挪回标题右侧
   同一行；选项胶囊条（全部点位 / 我的印章墙、商品分类）去掉白底通栏，直接铺在页面
   底色上。**聊天页与 AI 助手页例外**，它们的顶栏是沉浸式对话的一部分，桌面仍保留
   深绿渐变。

2. **个人中心头像下面那栏「印章 / 订单 / 消费」要删**。三个数字本来就是从下面
   「我的印章墙」和「我的订单」里能看到的重复信息，且用了 `margin-top:-24px` 压住
   hero 下沿（手机端常见的「卡片浮起」手法），在电脑宽屏上这个浮起效果意义不大。
  删掉卡片后必须连带处理两处：hero 的 `padding-bottom` 从 40px 改回 22px（原来多出来的
   18px 就是给浮起卡留的），并新增 `.hero-mine + .pad-x { padding-top: 14px }`，否则
   印章墙卡片会贴死 hero 下沿。

3. **导航右上角原来是姓名首字，要改成头像图片**。原来写的是
   `<img v-if="avatarUrl">` + `<template v-else>{{ (user.name || '游').slice(0,1) }}</template>`，
   没自定义头像的用户看到的是一个圆角方块里孤零零一个汉字。改成直接
   `<img :src="avatarSrc">`：`avatarSrc`（visitor.js:500-503）本身就是
   `avatarUrl || window.ZQProfile.defaultFor('buyer')`，已经带默认艺术头像兜底，
   不需要再在模板里分支。

另外顺手修了村内地图页的标题：它是唯一一个把标题写成裸 `<b class="topbar-title">`
的页面（别处都是 `.topbar-title > h1`），吃不到字号规则，桌面端标题比别的页小一号。

## 关键决策与取舍

- **桌面顶栏做成「透明标题区」而不是「保留深绿但缩窄」**。备选方案是给
  `.topbar` 加 `border-radius` 做成一块圆角色卡、或干脆在桌面 `display:none` 只靠导航
  高亮表示当前页。前者仍是色块、仍割裂；后者会让子页面（点详情、商品详情、订单详情）
  失去页面标题，用户不知道自己点进了什么。透明标题区是唯一同时满足「不割裂」和
  「有标题层级」的做法。
- **聊天 / AI 助手页顶栏不跟着改**。这两页是 `height:100dvh` 的纵向 flex 全屏页，顶栏
  是对话的一部分而不是页面导航；改成浅色后消息区和顶栏会糊成一片。代价是要多写
  6 条 `html[data-theme=...] .im-page > .topbar` 的特例规则，可接受。
- **头像不做「有图用图、无图用首字」的两套视觉**。默认头像是 `assets/img/avatar-visitor.svg`
  里画好的艺术头像，比首字更像头像；两套视觉还会让 34px 的小方块在不同用户之间跳跃。

## 踩坑与排查过程

1. **主题包把桌面标题区又涂成了实色方块**。改完 `light` 主题看着挺好，切到深色/暖阳/
   青墨就变回一块硬边方块。根因：三份主题包（theme-dark.css:218、theme-warm.css:216、
   theme-ink.css:216）都有 `html[data-theme="x"] .topbar { background: var(--surface) }`，
   特异度 0,2,1，压过新写的桌面 `.topbar`（0,1,0）。修法是在 visitor.css 的桌面媒体查询里
   补同特异度的 `html[data-theme="dark"] .topbar, ... { background: none; border-bottom: 0 }`
   （同特异度、文件更靠后，胜出），并对沉浸式两页单独放行回渐变。

2. **主题包给宽屏 body 刷了近黑色**。深色主题下桌面四周露出一圈近黑 `#0E1211` —— 那是
   当年「手机壳模拟器」时代给屏幕外区域刷的外框底色（`@media (min-width:620px)`）。
   合并成一套自适应页面后 body 直接铺满，这个块就成了纯污染。三份主题包各删一段。

3. **探测脚本拿到的是隐藏的 topbar**。第一次量 `.topbar` 的 computed style，结果全是
   `w=0/h=0`，误以为样式没生效。真因是页面里同时存在十几个 `v-if` 分支的 `.topbar`，
   `document.querySelector('.topbar')` 命中的是另一个视图里没渲染的那一个。做法：先按
   `getBoundingClientRect().width > 0` 过滤出可见元素再量。

4. **run_code 里用 `String.raw` 拼探测脚本会炸**。模板字符串嵌套时 `String.raw` 后面直接
   跟反引号，被解析成函数调用，报 `TypeError: String.raw(...) is not a function`。
   改成把浏览器端表达式用数组 `join('\n')` 拼成普通字符串、再用 `JSON.stringify` 嵌进
   生成的脚本文本，稳定且不用处理转义。
