- 日期：2026-09-28

## 做了什么、为什么

把本地项目首次推送到公开仓库 TheSixPasserby/zhanqi-ai-platform；
建立跨工具的 agent 行为约束（AGENTS.md，CLAUDE.md 仅作引用）；
建立本机制本身——每次提交随附工作日志与共享记忆。

## 关键决策与取舍

- 约束文件选 AGENTS.md 而非各工具各写一份（.cursorrules 等）：
  AGENTS.md 是 Codex / Cursor / Gemini CLI 等的共同标准，只维护一份防漂移；
  Claude Code 只认 CLAUDE.md，故用 `@AGENTS.md` 导入而不是复制内容。
- CLAUDE.md 没用符号链接指向 AGENTS.md：团队部署机是 Windows，
  git 符号链接在 Windows 上默认还原成纯文本文件，行为不可靠。
- `dist/` 的 24MB jar 保留入库：README 把它定位为「双击即用」的交付物，
  排除它会破坏一键部署承诺；`server/target/` 则排除。
- 工作日志按「一提交一文件」而不是单文件追加：多分支并行时
  单文件必然合并冲突，分文件天然无冲突。

## 踩坑与排查过程

- **险些泄密**：`config/application.yml` 里有成员本机 MySQL 真实口令，
  而仓库是公开的。推送前 grep 密钥类字段才发现。已 gitignore 该文件、
  提交口令留空的 example 模板，本地文件未动所以部署不受影响。
- 本机（macOS）没有全局 git 身份，首次提交报 "Author identity unknown"。
  用仓库级 `git config user.name/user.email`（GitHub noreply 邮箱）解决，
  没有污染全局配置。新成员首次提交大概率遇到同样报错。
