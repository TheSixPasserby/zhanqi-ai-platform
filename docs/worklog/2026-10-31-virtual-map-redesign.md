# 虚拟地图视觉与图标重做：分层矢量底图 + HTML 标签避让

- 日期：2026-10-31
- 作者：lead（DeepSeek Harness agent）
- 分支 / PR：feat/virtual-map-ai-split-4themes（第 31 轮）

## 做了什么、为什么

第 31 轮需求①：地图要「不简陋、图标美观、文字不重合、有艺术感、可缩放」，
只重做视觉与图标，**保留现有页面逻辑**（三端调用方式不变）。

旧版两个硬伤：

1. **底图简陋**：几块纯色矩形 + 几条线，没有任何地形质感。
2. **文字重合**：标记点和标签都画在 SVG 里，标签是 `<text>`，随地图一起缩放，
   相邻点位的标签互相压盖；放大后字号跟着变大，压盖更严重。

新版：

- 底图做成分层矢量插画，图层顺序固定：纸底渐变 → 3 块农田（带垄沟）→ 9 处树冠簇 →
  主渠 / 西侧支渠 / 东南水塘 → 4 条道路（主干带白色虚线中心线）→ 十八坊建筑群与林盘院落 →
  村口广场 → 边界虚线 → 纸纹 → 暗角。全部是 SVG，无位图、无外部字体。
- 标记与标签移到 **HTML 图层**（`.vmap-pins`，绝对定位覆盖在 SVG 上），
  图标换成五类语义化 SVG 字形：点位=星、研学=书、民宿=屋顶、农事=麦穗、活动=日历。
- 标签自动避让：每个标签有 80 个候选槽位（5 圈 × 16 方向），
  按「点位类优先 → 先试全名 → 再试短名 → 都放不下才隐藏」的顺序放置，
  逐个做矩形相交判定，保证任意两个可见标签不重叠、不出画布。

对外 API 完全兼容，只新增了一个 `focus(x, y, z)` 与一个 `relayout()`。

## 关键决策与取舍

- **标签放 HTML 层而不是继续在 SVG 里避让**。SVG 量不到文字实际渲染宽高
  （`getBBox` 要渲染后才准，且随 `scale` 变化），HTML 的 `offsetWidth/offsetHeight`
  才是可靠输入。代价是必须自己保证「HTML 图层与 SVG 视口严格对齐」——
  用 `preserveAspectRatio="xMidYMid meet"` 加 `side = min(clientWidth, clientHeight)`
  把两层都按同一个正方形居中，缩放/平移只改一层的位置换算。
- **缩放时标签不反向缩放**（旧版注释声称「保持视觉大小恒定」，但代码没实现）。
  理由：标签随地图放大的体验其实更好——放大就是为了看清，反向缩放会让文字永远那么小；
  真正的「不重合」靠避让算法保证，不靠固定字号。
- **放不下时先截断再隐藏**。直接隐藏会让密集区显得空（第一版就是这样，23/43 被隐藏）。
  截断规则：去掉「战旗村」「乡村」「天府粮仓·」这类前缀，超过 5 字加省略号；
  hover/focus 时恢复全名。
- **坐标仍用 0-100 百分比**，不改成像素：地图要缩放平移，百分比在任何缩放级别、
  任何窗口尺寸下都不用换算，也不会错位。

## 踩坑与排查过程

- **43 个标记只渲染出 1 个**。旧实现全篇用 `m.id` 当唯一键，但游客端传进来的
  `mapMarkers` 形状是 `{key, kind, refId, name, subtitle, cover, x, y}` —— **没有 id**。
  于是所有标记的 `data-id` 都是 `undefined`，去重后只剩第一个。
  这个 bug 用造的数据测不出来，只有接真实接口才暴露。修法是 `markerKey()`
  依次取 `id → key → refId → 下标`。
- **HTML 图层与 SVG 对不齐**：第一版直接把 `.vmap-pins` 铺满整个 stage，
  但 SVG 在非正方形容器里会上下留白（`meet` 行为），标记整体偏上。
  改成「量出 `side`，把 `.vmap-pins` 设成 `side × side` 并居中」后才对齐。
- **拖拽结束会误触发选点**：`pointerup` 后紧跟的 `click` 把「拖到哪就选到哪」。
  加 `suppressClick` 标记（位移超过 3px 才算拖拽），并在 `click` 里消费掉。
- **「再点一次取消选点」不能做成「下一次点击无条件取消」**：用户想微调位置时
  点一下反而清空，很难用。改成「点在同一处 ±6% 范围内才取消」。
