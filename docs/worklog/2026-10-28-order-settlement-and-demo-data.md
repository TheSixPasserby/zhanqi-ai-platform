# 订单结算与权限修正 + 演示数据重建 + 三个界面 Bug

- 日期：2026-10-28（第二轮）
- 作者：lead（DeepSeek Harness Team）

## 做了什么、为什么

第一轮把订单履约改成了「商家接单/发货 → 完成」，但留下两个结构性问题：
**完成订单的权限在商家手里**，而且**没有任何资金结算概念**。
本轮按需求把「完成」的主动权交给买家，并把「确认收货」做成结算的唯一触发点。

同时处理三件事：
1. 清理不符合新购买逻辑的旧预约类订单（旧流程的「核销态」）；
2. 建了演示账号「小帅」，覆盖全部订单状态与举报全流程；
3. 修三个真实界面 Bug（扇形图口径、聊天空白、消息图标）。

## 关键决策与取舍

- **完成权限只能给买家**。商家自己点完成等于既当运动员又当裁判，而且钱款结算就发生在这一步。
  `POST /orders/{id}/complete` 直接删掉（404），新增 `/receive` 仅 buyer 可调。
  smoke-test 里原本三条「商家完成」断言同步改写成「商家不能完成」+「买家确认收货」+「结算流水」，**没有弱化**。
- **结算用「流水表 + 汇总列」而不是只建流水**。商家看板与列表要在一次查询里拿到已结算金额，
  每次都聚合流水会随订单量增长变慢；汇总列冗余但写入点只有一处（`SettlementService`），
  且脚本重算时用聚合而非累加，保证重复执行不会翻倍。
- **退款不删流水，只追加负数**。删流水会让「这笔钱到底进没进过账」变得无法追溯；
  正数 + 负数并存才是完整账目。未结算的订单退款不冲减（钱本来就没到商家）。
- **管理员禁止改 `completed`**。这是唯一会造成「结算金额凭空增加」的越权路径，
  在 `AdminService.updateOrder` 里直接 400，并在后台下拉里把该选项置灰 + 文字说明。
- **演示账号 id 用 u9001 而不是 u13**（踩坑后改的，见下）。
- **演示数据不进启动链路**。`seed-demo-xiaoshuai.sql` 由 `tools/seed-demo.js` 显式执行，
  否则每次启动都会灌一遍演示订单，还会污染 `reset.bat` 的语义。

## 踩坑与排查过程

1. **演示账号主键撞车（最隐蔽的一个）**。第一版用了 `u13`，灌完发现小帅名下有 45 笔订单，
   其中 27 笔是「冒烟测试游客」「界面测试游客」的残留。
   根因：`Db.nextId()` 按「当前行数 + 1」取号，用户表 12 条时自检脚本注册的测试账号**正好也叫 u13**，
   于是它们下的单全挂到了小帅名下。
   修法：演示账号改用 `u9001`（远在顺序号之外），并把这 27 笔测试残留连同它们的日志/结算/聊天引用一起清掉。
   教训：**任何写死 id 的演示数据都要先查 `Db.nextId()` 的取号规则**。
2. **`total=0` 的扇形图用例一开始没测对**。我只把 `total` 置 0，但 `spots` 还有 14 个，
   新逻辑是「段数取 min(total, spots.length)」，于是仍然画出 14 段 —— 这是**正确行为**，
   不是 bug。真正的空态场景是「spots 为空」，补上这个用例后通过。
3. **商户端 autosize 不会在清空后立刻回落**。`el-input` 的 autosize 依赖内容变化重算，
   `draft=''` 之后高度要等 Vue 更新才回落，测试里立刻读会读到旧值。
   改为断言「内容已清空」+「无空白气泡」，高度回落交给 autosize 本身（已在真实页面确认会回落）。
4. **PC 端页面在 430px 视口下会被设备检测跳到手机版**，导致 `#pc` 不存在、`__vue__` 读不到。
   测试时要么用宽视口，要么显式 `sessionStorage.setItem('zq.visitor.forceMobile','0')`。
5. **`browser-check` 的「登录页必须是空的」断言需要改口径**。演示账号小帅必须保留登录痕迹
   才能演示快捷登录，旧断言把正常演示数据判成失败。
   改法是断言**更严格的属性**：只出现买家账号、不含 password/rememberToken、
   且页面渲染与后端账号数一致 —— 不是放宽成「不检查」。

## 遗留问题与下一步

1. **「待付款」状态没有实现**。项目无支付通道，需求里的「待付款」用 `pending（待商家确认）` 表达，
   演示订单 ox1 即是这种状态。要真做需要接支付网关并新增 `unpaid` 状态。
2. **结算不回滚库存**（与上一轮一致）：退款只冲减金额，商品库存不增加。
   若业务要求「退款即回库存」，在 `ReportService.applyRefund` 补一次回滚，注意别与 `cancel` 重复。
3. **`settledAmount` 是读-改-写更新**，没有用 SQL 表达式自增。单进程低并发够用；
   生产应改成 `UPDATE merchants SET settledAmount = settledAmount + ?`。
4. **演示数据脚本依赖本机 mysql CLI 路径**（可通过 `MYSQL_BIN` 环境变量覆盖）。
   换机器部署时要确认路径，或改用 JDBC 版本。
5. **小帅的 6 条举报里，凭证都是同一张极小占位 SVG**。真实演示如需不同图片，
   替换 `tools/gen-demo-xiaoshuai.js` 里的 `EVID` 常量后重新生成即可。
